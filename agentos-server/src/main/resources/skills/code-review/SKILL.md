# 代码评审指南

## 步骤

1. **圈定范围**：先用文件读取工具读取变更涉及的文件，理解调用关系。
2. **正确性优先**：检查边界条件、空值处理、资源关闭与并发安全。
3. **可维护性**：命名是否达意、职责是否单一、是否存在重复逻辑。
4. **测试完备性**：确认新增行为有对应测试覆盖，测试断言针对行为而非实现。
5. **输出结论**：按严重程度分级列出问题，并给出可执行的修改建议。

## 约束

- 只评审给出的变更，不臆测未读代码的行为。
- 每个问题必须引用具体文件与位置。
- 阻断级问题（正确性/安全）与建议级问题分开列出。

## 输出格式

```
## 总体结论
## 阻断级问题
- <文件:位置> 问题描述 → 修改建议
## 建议级问题
## 测试覆盖情况
```
